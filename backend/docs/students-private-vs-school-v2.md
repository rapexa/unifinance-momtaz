# مشخصات v2: دانش‌آموز خصوصی / مدرسه‌ای و قرارداد مدرسه

این سند **جایگزین فهم قبلی** در `school-contract-and-registration-types.md` است (تفکیک قرارداد مدرسه از رکورد دانش‌آموز).

> **مرجع مالی فعلی (2026-08):** مدل پرداخت/مانده per-student در  
> [`school-per-student-billing-phases.md`](./school-per-student-billing-phases.md)  
> بخش‌های پرداخت، مبلغ واحد، و cash-only این سند برای مسیر محصول جدید **منسوخ**اند. آنچه پایین به‌عنوان «اصول هویت» آمده همچنان معتبر است؛ آنچه با برچسب ~~منسوخ~~ آمده دیگر اجرا نمی‌شود.

## ۱) اصول هویت (معتبر)

| اصل | توضیح |
|-----|--------|
| هر دانش‌آموز یک `Student` است | چه خصوصی، چه مدرسه‌ای |
| نوع ثبت‌نام روی دانش‌آموز | `PRIVATE` یا `SCHOOL` |
| قرارداد مدرسه موجودیت جداست | نام، تعداد توافقی، **مبلغ کل قرارداد** |
| ثبت مدرسه جدا از ثبت دانش‌آموز | دکمه «افزودن مدرسه» / «افزودن دانش‌آموز» |
| دانش‌آموز مدرسه‌ای | لینک اجباری به `school_contract_id`؛ نام مدرسه از قرارداد |

## ۲) مدل مالی فعلی (جایگزین بخش قدیمی)

| موضوع | رفتار فعلی |
|--------|------------|
| مبلغ قرارداد | `total_amount_cents` مستقیم (نه تعداد × واحد) |
| دانش‌آموز مدرسه‌ای | مثل خصوصی: مبلغ ثبت‌نام، نوع پرداخت، پلن، سهم مشاور/نقش‌ها (بدون نحوه برگزاری و اسم/آدرس مدرسه متنی) |
| پرداخت جدید | فقط روی `student_id` (خصوصی یا مدرسه‌ای) |
| ایجاد پرداخت فقط با `school_contract_id` | **منسوخ / رد می‌شود** |
| پرداخت‌های قدیمی فقط‌قراردادی | خواندنی/تاریخی با برچسب `LEGACY_SCHOOL`؛ در `paid_total` جدید شمرده نمی‌شوند |
| مانده دانش‌آموز | `enrollment − Σ PAID(student_id)` |
| مانده مدرسه | `total_amount − Σ PAID دانش‌آموزان همان قرارداد` |
| حقوق / کمیسیون | روی پرداخت دانش‌آموز مدرسه‌ای مثل خصوصی فعال است؛ فقط legacy قرارداد cash-only می‌ماند |

جزئیات فازبندی و وضعیت پیاده‌سازی: سند phases.

## ۳) UI (معتبر با اصلاح مالی)

| محل | رفتار |
|-----|--------|
| دانش‌آموزان — تب خصوصی | دانش‌آموزان `PRIVATE` |
| دانش‌آموزان — تب مدارس | لیست قراردادها؛ کلیک → دانش‌آموزان مدرسه (بدون ستون مالی قرارداد) |
| پرداخت‌ها → مدارس | ثبت‌شده/توافق، مبلغ کل، پرداخت‌شده (دانش‌آموزان)، مانده، خلاصه وضعیت؛ در صورت وجود: مبلغ تاریخی جدا |
| ثبت پرداخت مدرسه‌ای | مدرسه → دانش‌آموز همان مدرسه → مبلغ |

---

## ۴) معیار پذیرش هویت (هنوز معتبر)

1. ثبت دانش‌آموز همیشه `Student` می‌سازد؛ نوع خصوصی یا مدرسه‌ای مشخص است.
2. خصوصی: آنلاین/حضوری + فیلدهای پرداخت.
3. مدرسه‌ای: انتخاب مدرسه + فیلدهای پرداخت فردی (طبق phases).
4. «افزودن مدرسه» جداست.
5. در منوی دانش‌آموزان: خصوصی vs مدارس جدا؛ کلیک مدرسه → دانش‌آموزان آن.
6. ~~پرداخت قرارداد فقط روی مدرسه~~ → **جایگزین:** پرداخت روی دانش‌آموز مدرسه.
7. با انتخاب «مدرسه‌ای» در فرم دانش‌آموز، قرارداد ساخته نمی‌شود.

## ۵) خارج از اسکوپ (مگر درخواست بعدی)

- ساخت خودکار N دانش‌آموز هنگام ثبت مدرسه
- تخصیص خودکار یک پرداخت قدیمی قرارداد به چند دانش‌آموز
- بلاک سخت وقتی جمع مبالغ ثبت‌نام ≠ قرارداد (فقط هشدار)
